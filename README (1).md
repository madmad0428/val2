# 프롬프트 기법이 LLM의 e스포츠 경기 예측 정확도에 미치는 영향

> VCT 2026 프로 경기 맵 승패 예측을 과제로, Few-shot · Chain-of-Thought · Role
> prompting 세 프롬프트 기법을 비교한다. 그리고 **그 비교 결과가 어떤 측정 조건
> 위에서 성립하는지**를 함께 검증한다.

Claude Haiku · Python · 440개 시나리오 · McNemar 검정 · 혼동행렬 · 개입 실험(swap)

---

## 한눈에 보기

이 연구가 답하려는 두 질문:

1. **[RQ1]** 프롬프트 기법에 따라 LLM의 경기 승패 예측 성능이 실제로 달라지는가?
2. **[RQ2]** 실험 중 관찰된 "먼저 제시된 팀(팀A) 쪽으로의 예측 쏠림"은
   모델의 **위치 편향**인가, 아니면 **측정 과정의 결함**인가?

두 질문의 답은 모두 **"측정 조건을 통제하고 나면 그렇지 않다"**로 수렴한다.
겉보기 성능 차이와 예측 쏠림은 대부분 **평가 파이프라인(파서·출력 형식)의
산물**이었고, 이 결론은 세 개의 독립적 검증 경로가 같은 곳을 가리키는
**삼각검증**으로 뒷받침된다.

---

## 핵심 결과

### RQ1 — 기법 간 성능 차이는 측정 조건이 만든 것이었다

| 조건 | Few-shot | CoT | Role | 최대 격차 | 유의성 |
|---|---|---|---|---|---|
| 본실험 (텍스트 파싱, max_tokens=3000) | 58.6% | **65.5%** | 63.6% | 6.9%p | CoT·Role > Few-shot (p<0.05) |
| 파서 교정 후 (+ 수동 판독) | 85.0% | 86.1% | **87.0%** | 2.0%p | 모든 쌍 차이 없음 |
| JSON 출력 통제 재실험 | 90.5% | 91.6% | 89.1% | 2.5%p | (CoT-Role만 단독 p<0.05, 보정 시 소멸) |

- 본실험에서는 CoT가 1위처럼 보였지만, **파서를 교정하자 순위가 역전**되고
  (Role ≥ CoT ≥ Few-shot) **Bonferroni 보정(α=0.0167) 하에 모든 기법 쌍의
  유의한 차이가 사라졌다.**
- → **교정 후 세 기법 간 실질적 성능 차이는 없다.** 본실험의 격차는 상당 부분
  각 기법의 응답 구조와 파서가 얼마나 정합하냐의 문제였다.

### RQ2 — 팀A 쏠림은 위치 편향이 아니라 파서 결함이었다

- 혼동행렬에서 **팀A 재현율 0.90 vs 팀B 재현율 0.31**의 강한 비대칭 발견.
  실제 데이터의 팀A 승률은 47.3%로 오히려 낮았으므로 클래스 불균형으로는 설명 불가.
- 처음엔 LLM 위치 편향(선행연구 존재) 가설을 세웠으나, **전 응답 전수 검사** 결과
  팀명 추출 함수(`extract_winner`)가 응답 말미에 두 팀명이 함께 등장할 때
  **무조건 팀A를 반환**하는 구조적 결함으로 확인됨. 이 버그가 각 기법
  **전체 오답의 46.3~77.5%**를 차지했다.

### 삼각검증 — 세 경로가 같은 결론에 수렴

| 검증 경로 | 방식 | 결과 |
|---|---|---|
| ① 재분석 | 교정 파서로 1,320개 응답 재분류 | 정확도 85~87% 수렴, 쏠림 소멸 |
| ② 재실험 | JSON 출력 강제 후 재호출 | 정확도 89~92% 수렴 |
| ③ 개입 실험 | 팀 제시 순서를 직접 뒤집음(swap) | swap 일관성 96~97% ≈ rerun 자연변동 98~99% |

세 독립 경로가 모두 "순서·기법이 아니라 측정 도구가 원인"을 가리킨다.

## 방법론에서 신경 쓴 것

- **데이터 누출 차단**: 12라운드(하프타임) 시점 스탯만 입력. 경기 전체 스탯을
  주면 답을 알려주는 꼴이 되므로 라운드 시점으로 제한.
- **표본 균형**: 587개 맵 중 440개 선별, 접전(스코어차 ≤5) : 일방(≥6)을
  50:50으로 배분해 "스탯 우세팀 찍기"로 정확도가 과대평가되는 것을 방지.
- **재현성 통제**: temperature=0, max_tokens=3000 고정, 호출 간 0.5초 딜레이,
  총 1,320회 호출(440 × 3기법).
- **비결정성 대조군**: temperature=0에서도 API가 완전히 결정적이지 않음을 인정하고,
  순서 효과를 자연 변동과 분리하기 위해 **rerun(동일 프롬프트 재실행) 대조군**을 설계.
- **자동화의 한계 인정**: 자동 파싱 불가 10건은 연구자가 원문을 직접 판독.
  모델이 승자를 구 팀명으로 지칭한 사례 등, 자동 파서가 못 잡는 오류 유형을 기록.
- **스탯 변조 검증**: 실제 승리팀 스탯을 열세로 뒤집어 입력했을 때 모델이
  변조된 우세팀을 택함을 확인 → 결과 암기가 아니라 실제 스탯 분석임을 입증.

## 정직하게 남긴 한계

- JSON 출력 통제는 파싱 오류를 없애 정확도를 교정하는 **동시에**, 세 기법의 최종
  판단을 모두 "스탯 우세팀 선택"으로 수렴시켜 **기법 간 변별력을 흐린다**.
  측정 정확성과 변별력을 동시에 만족시키기 어려운 트레이드오프로 남는다.
- 접전 경기에서 swap 불일치가 더 잦은 경향은 관찰됐으나, rerun 대비 McNemar
  검정에서 유의하지 않아(모든 기법 p>0.21) **확증하지 못한 잠정적 관찰**로 남긴다.
- 예시 순서(recency), 역할 설명의 구체성, 예시 대표성 등은 본 연구에서 통제·검증하지 않음.

## 실행 방법

> ⚠️ API를 호출하는 스크립트(`vct_experiment_440.py`, `vct_run.py`,
> `rerun_cot_440.py`, `test_flip.py`)는 코드 상단의 `api_key`에 본인의
